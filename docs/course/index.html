Freddy Learning Elyra Workspace

Freddy builds his notes app with coding agents, and for months he has done it the way most people start: four terminal tabs, a lot of hope, and no idea which tab was waiting for him. This course is the fifteen chapters that move him into one window — from the first thread to agents that check their own work, try what they built, run on a schedule, and reach him on his phone when they need him.

Who this is for

You already use a coding agent — Claude Code, Codex, Elyra, Pi or another — and you have felt the edges of doing it from a terminal: the agent that has been waiting for an answer for twenty minutes, the change you cannot quite see, the second task you did not start because the first one owned the folder. Elyra Workspace is a desktop app for exactly that situation.

You do not need to have taken the other courses. Freddy is a small developer with a small notes app, and the examples use his project. Substitute your own everywhere you see his; nothing here depends on what the app does.

How to read it

Every chapter is built the same way: the problem (why this matters at all), the hard way (what you do without the feature, and where that breaks), then the feature itself. The order is deliberate: the early chapters give you a window you can trust, the middle ones let you run several things at once, and the last ones let you walk away. Walking away before you can trust the window is how people get hurt.

One honest note before we start. Workspace does not make an agent smarter. It makes the agent's work visible, parallel, checkable and safe to leave. The agent is still the agent you installed, with its own strengths and its own bills, and this course says so wherever it matters.

What you need

A Mac with Apple Silicon (M1 or later) on macOS 12 or later, git, and at least one coding agent installed and signed in. Chapter 2 lists them and where each is installed from. Intel Macs are not supported. Elyra Workspace itself is free to use; the agents are what they have always been, so any subscription or API cost is theirs, not Workspace's.

The chapters

  1. 1. Four Terminal Tabs and a Lot of Hope — Why agents in a terminal stop scaling at the second task, and the four ideas Workspace is built from: project, thread, provider, turn.
  2. 2. The First Launch — Install the app, check that it can find your agents, add a project, and send the first message.
  3. 3. Talking to an Agent — The message box, the row under it, and the choices that decide what a thread is allowed to do: agent, model, effort and permission mode.
  4. 4. Reading What the Agent Did — Tool cards, approvals, questions and plans: how to see what an agent is doing, say yes or no, and put the files back when it was wrong.
  5. 5. Changes, Commits and Pull Requests — Review one turn at a time, comment on a line and send it back, commit with a message the agent writes, and take a branch through a pull request without leaving the window.
  6. 6. Many Threads, One Project — The sidebar as a status board, tabs and split chat, side chats for questions, and forking, handing off and getting a second opinion.
  7. 7. Worktrees and the Parallel Fix — Why two threads should not edit the same folder, how a worktree solves it, how Grove gives each one a running app, and how best of N turns one task into a small contest.
  8. 8. Teaching the Project — The Context tab: notes, recaps, pinned messages, project instructions, rules agents learn, and one setup of servers and skills that every agent shares.
  9. 9. Done Means Green — Goals that keep an agent going, budgets that stop it, and a check command that makes finished mean the tests passed.
  10. 10. The Browser, and Agents That Try What They Built — A browser in every thread: point at what is wrong, hand the agent the errors, see before and after, and let it click through the flow, then save it as a journey that is replayed like a test.
  11. 11. Files, Search and the Terminal — Find anything with one key, read and edit files beside the conversation, and keep a terminal in every thread, starting in the right folder.
  12. 12. Work That Starts Itself — Automations that run on a schedule, a task board that starts threads, and the Félagi integration for people whose tasks live in an issue tracker.
  13. 13. Leaving the Desk — What happens to the agents when you close the window or quit, how an interrupted turn resumes, what the summary tells you when you come back, and how to answer from your phone.
  14. 14. Agents That Run Agents — The agent gateway: let one agent split a job, start a thread for each part and wait for them, connect Claude Desktop or Codex, and read the audit log of every call.
  15. 15. Keeping It Healthy — Where your data lives, what Settings is for, how updates verify themselves and go back, what the app sends where, and what to do when something is wrong.
